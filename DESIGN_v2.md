# Semantic Gravity Wells v2: design

Single source of truth for the v2 rerun. v1 (arXiv:2601.08070) had bugs listed in
"Known v1 bugs" below; v2 reruns everything with fixed code and reports whatever the
fixed analysis finds. Deadline: code, data and GPU run done by 25 Nov 2026 ~12:00 IST.

## Question

When an instruction-tuned model (Qwen2.5-7B-Instruct) is told "Do not use the word X"
for a question whose natural one-word answer is X, how does the violation rate depend
on the baseline pressure toward X, and what inside the model differs between prompts
that violate and prompts that comply?

## Data (2,500 prompts, 500 per category)

Five categories, as in v1 (docs/specification.md section 3): idioms, facts, common
sense, creative, out-of-distribution (OOD). Every external source is snapshotted to
`data/sources/` with retrieval date and URL, so the dataset is reproducible from files.
All randomness is seeded (seed 42). The final prompt set is published in the repo.

- Idioms: baiango/english_idioms idioms.csv (pin the commit hash), plus Wiktionary idioms,
  used where baiango ran short: only 427 accepted baiango items exist. Templates I1–I3.
- Facts: Wikidata SPARQL results saved as JSON. Templates as v1.
- Common sense: ConceptNet questions were judged, but only 46 passed the blind judge. So the
  common-sense questions were generated by an LLM (gpt-6.1-terra via Codex), one request per
  target word, and judged blind by gpt-6-luna under the same acceptance rules.
- The source of every item is in its `source_trace` field.
- Creative and OOD: generated by an LLM, one request per target word. Target words are
  chosen first (wordfreq Zipf 3.5–6.0, alphabetic, deduplicated across the whole
  generated set), and each request asks for K=5 candidate prompts for that one word.
  So duplicates cannot arise; no dedup loop.
- Global rule: a target word appears in at most 2 categories (as v1).
- Code filters (no LLM): target not in the question (word-boundary, case-insensitive);
  question ends with a blank or asks for one word; ASCII; length limits.
- LLM judge (one pass, cheap model): returns JSON {best_one_word_answer, top3,
  is_X_best, ambiguity 0–10, leaks_answer, naturalness 0–10}. Accept if is_X_best,
  ambiguity <= 3, not leaks, naturalness >= 7 (v1 rules). At most 25 prompts per judge
  call, to keep the judge sharp.
- Pressure P0 (below) is measured on Qwen for every accepted candidate. Then per category
  pick 500 balanced over P0 bins [0,.2),[.2,.4),[.4,.6),[.6,.8),[.8,1]; aim 100 per bin,
  fill shortfalls from neighbouring bins, and log the final counts. Low-pressure prompts
  are kept: they are valid points on the curve. (v1 claimed a P0 >= 0.2 filter it never
  applied; v2 states the real rule.)
- For creative/OOD, among the accepted candidates for a word keep one chosen at random
  (seed 42), not the highest-P0 one: choosing by P0 would push every category into the
  top bin and select prompts on the quantity being studied. State this in the paper.
- The judge is blind: it never sees the intended target. is_X_best is computed in code
  as judge's best answer == target (case-insensitive). Also reject items flagged offensive.
- Multi-token targets are allowed (most capitals are multi-token for Qwen). Mechanistic
  metrics use the target's first token; every mechanistic result is also reported on the
  single-token subset as a robustness check.

## Prompts given to Qwen

Use the chat template (tokenizer.apply_chat_template with add_generation_prompt=True,
default Qwen system prompt). The user message is:

Baseline:
```
Answer with exactly one English word.
Question: {question}
Answer:
```
Negative:
```
Answer with exactly one English word.
Do not use the word "{X}" anywhere in your answer.
Question: {question}
Answer:
```

The decision position is the first assistant token (the logits after the generation
prompt).

## Measurements per prompt (GPU, Qwen2.5-7B-Instruct, bf16)

1. P0 and P1: exact probability that the answer's first word is X, under baseline and
   negative. Defined as the sum over surface variants v in {X, x, X.capitalize(), X.upper()}
   (deduplicated, each with and without a leading space) of
   P(canonical tokens of v) * P(next token does not start with a letter or digit | v).
   Each variant is a distinct complete first word, so there is no double counting and
   the sum is a probability (assert P <= 1 + 1e-4).
2. Greedy completion under each condition (max 8 new tokens).
3. 16 samples per condition, temperature 1.0, top_p 0.9, max 10 new tokens, seeded.
   Batched generation uses LEFT padding (assert tokenizer.padding_side == "left").
4. Violation: X appears as a whole word (case-insensitive, word boundary) in a negative
   completion. Per prompt: violation rate = violations / 16. Greedy failure = greedy
   negative completion contains X.
5. Logit lens, every layer l = 0..27, at the decision position, both conditions:
   target first-token probability from norm(resid_post_l) @ W_U. Take resid_post via
   hooks on the decoder layer outputs (pre final norm), so the final norm is applied
   exactly once. Golden check: at the last layer this equals the model's real output
   distribution (max abs diff < 1e-3 in fp32 compare).
6. Attention at the decision position, negative condition, every layer, mean over heads:
   mass on the target-mention tokens inside the instruction (TMF), on the negation tokens
   "Do not" (NF), and on the question tokens. Token spans found by character offsets
   (offset_mapping), checked by decoding the span back to text. Requires eager attention.
7. Direct logit attribution per layer: attention output and MLP output at the decision
   position, each projected onto the target first-token unembedding direction, using the
   final norm's scale from the real final residual (standard linearised DLA). Both
   conditions.
8. Activation patching on a subset of 250 prompts (50 per P0 bin, mixed outcomes),
   next-token distribution only (single forward pass, no KV cache, no generation, so no
   cache reuse bug is possible). For each layer l, run the negative prompt with the
   residual stream (type R) or the attention output (type A) at the decision position
   replaced by its value from the baseline run. Effect = change in target probability
   P1. Golden checks: patching nothing reproduces P1 exactly; patching the residual at
   the last layer reproduces P0's last-layer distribution. Report each type separately,
   split by outcome, never averaged across types.

Everything is saved per prompt to Parquet/JSONL with the prompt id. Nothing is typed by
hand into figure scripts; every figure and table number is computed from saved outputs.

## Analysis (prompt level)

- Violation rate vs P0: logistic regression on samples with prompt-clustered bootstrap
  (resample prompts, 1,000 draws) for CIs; report McFadden pseudo-R2 at sample level and,
  separately and labelled, R2 of the fit to bin means.
- Suppression (P0 - P1) for violating vs compliant prompts, compared within P0 bins
  (matched), because failures are selected on high P1.
- "Priming" signature (TMF > NF, or P1 > P0): rate among failures AND among successes,
  both reported, with the difference and a test. Same for any other proposed signature.
- DLA and logit-lens curves by outcome within P0 bins.
- Patching curves by type and outcome.

## Known v1 bugs this design removes

- Priming taxonomy had no base rate among successes and a rule different from the paper.
- Patching reused a mutated KV cache across patch runs.
- Logit lens applied the final norm twice at the last layer.
- P0 summed overlapping prefix variants then clipped to 1.
- CIs resampled samples instead of prompts; R2 undefined.
- No chat template; batched sampling without left padding.
- Figure numbers typed by hand; data not published.
